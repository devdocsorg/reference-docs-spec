# Inline Comment Rules

Each documented symbol gets one sentence saying what it is. Document parameter,
error/exception, and return types in the idiomatic framework. Use examples only
for nontrivial strings, arrays, small objects, enums, and numbers. Do not use
boolean examples, large composed examples, or complete import/setup samples.
Preserve true existing comments; correct false or stale comments only with a
ledger entry and source evidence. Config and environment files use plain
comments near keys.
